# OpenClaw与Obsidian自动化

## 背景

**目标:** 搭建一个以 Obsidian 为知识底座、以 OpenClaw 为执行入口的最小可用自动化系统，并用于服务 [[中国市场POD业务验证]] 与 [[跨境POD业务验证]]；当前先把本土线跑通，后续再把可复制部分迁到跨境。

**成功指标:**
- [x] 能清楚说明 OpenClaw、Obsidian、OrbitOS 三者的角色分工
- [x] 能在 OrbitOS 中完成一轮 `收件箱 -> 计划 -> 项目` 的闭环
- [x] 能定义 1 条与中国 POD 市场调研相关的最小自动化链路
- [ ] 能至少为一条业务线跑出 1 条真实候选题材并记录反馈信号

**限制条件:**
- 时间线: 先不设硬性截止日期，优先理清思路并跑通最小闭环
- 资源: 当前已有 OrbitOS 中文版 Vault，可直接在此基础上推进
- 依赖项: 需要先理解 OpenClaw 的使用方式与适用场景

## 备注

- 当前优先级不是追求复杂自动化，而是先建立正确的系统分工。
- 推荐的首条验证链路已更新为：先在中国线完成“抖音 / 小红书找款监控 -> `00_收件箱` -> [[中国市场POD业务验证]] 的样本台账与监控页 -> 候选题材或设计方向”，后续再复制到 [[跨境POD业务验证]]。
- 当前下一阶段不再扩概念，优先做真实闭环验证：先拿 1 条样本把“平台最优链路 -> 通用兜底 -> 主来源补锚 -> 学习深度升级”跑通。
- 当前状态更准确地说是：系统骨架已成，下一阶段重心转向“真实样本、角色偏好、项目验证、清理机制”这些血肉层建设。
- 检索层试点当前已经通过 3 条真实样本验证出价值，后续继续保持轻量“影子试点”即可，不急着扩成新系统工程。
- `heartbeat` 当前不要再按“是否开了”判断，而要按“是否真的减少手动检查和漏项”判断。
- 当前项目定位已经收紧为“自动化底座”，`POD` 业务层的宏观判断、渠道取舍、监控数据和题材验证默认转入 [[中国市场POD业务验证]]。
- 当前跨境不是独立并行线，而是本土线跑顺之后的复制目标；先把共通方法和平台差异记录清楚，比现在同时铺开更稳。
- 结构上现在已经保留中国 / 跨境两条业务线，所以后续不会再因为“要不要分项目”反复改架构；当前只需要继续守住执行先后顺序。
- 记忆蒸馏已经建立起第一轮真实落位，后续重点不是再解释流程，而是持续把稳定规则和偏好归位到长期记忆。
- 当前工程侧真正紧急的收口项已经做完，后续更适合转入“观察收益 + 真实样本持续喂养”的节奏。
- 整体架构研究已经完成 kickoff 收口，当前不再新增平行项目，只继续围绕 `Web Clipper` 闭环验证与 `heartbeat` 收益观察推进。
- `Obsidian` 生态这条线当前也不再按“装得越多越强”推进；`Bases` 已经在场，后续优先看它是否足够承接真实视图需求。
- 研究清理当前也形成了一个更稳的默认动作：先把线索吸收成判断，再把不再服务主线的条目降级归档，不让 `30_研究` 持续被历史噪音占满。
- 当前 `30_研究` 里的 `active` 已不再代表“今天看过”，而是代表“还需要继续推进或验证”。
- 归档层现在也不再是一个大仓库，而是继续分成“保留完整过程的证据归档”和“只保留入口的索引归档”两层。
- 后续这类会持续被新知识冲击的系统判断，不再主要靠旧研究页承载，而是优先写进判断型知识卡，并在卡内保留演化轨迹。
