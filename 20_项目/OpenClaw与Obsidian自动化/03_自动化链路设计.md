# 自动化链路设计

## 第一条要验证的链路

抖音 / 小红书找款监控 -> `00_收件箱` -> [[20_项目/中国市场POD业务验证/14_中国市场_T恤样本采集记录表]] -> 项目判断 -> 输出候选题材或设计方向

## 当前选定版本

当前最小闭环不做“脱离平台的离线选题”，而做“半自动、真可落地”的找款监控版本：

`抖音 / 小红书观察到值得记录的款或内容 -> 飞书发收件箱前缀 -> 谋士写入 00_收件箱 -> 录入 [[20_项目/中国市场POD业务验证/14_中国市场_T恤样本采集记录表]] -> 汇总到 [[20_项目/中国市场POD业务验证/12_中国市场_T恤平台找款与监控闭环]] -> 输出候选题材或下一步采样动作`

### 当前推荐触发方式

- 飞书里发：`收件箱：链接 + 一句为什么值得存`
- 如果已经是明确平台样本，也可以直接发：`研究：抖音/小红书链接 + 一句判断`
- 每条样本尽量保留“平台 + 时间 + 互动信号 + 是否带货”

## 当前升级方向：少手动监控版

在最小闭环已经跑通后，下一阶段升级为“少手动监控版”：

`飞书直接丢抖音 / 小红书样本 -> 谋士默认识别为平台样本 -> 自动补同题材对照样本 -> 更新监控台账 -> 汇总题材反馈`

### 升级后默认方式

- 不再要求每次先写 `收件箱：`
- 如果消息主要是抖音 / 小红书链接，或“链接 + 很短的题材提示”
- 默认按平台样本处理
- 优先进入监控台账与项目判断
- 如条件允许，再补 2-3 条同题材对照样本

### 适合这个版本的场景

- 你在抖音看到一条卖得动的 T 恤内容
- 你在小红书看到一个反复出现的图案 / 文案方向
- 你想知道某个题材是不是平台上正在连续出现
- 你需要把“今天看到的款”沉淀成后续还能复用的监控数据

### 为什么选这个版本

- 这条链路已经和你当前真实系统能力对齐
- 前端输入已经跑通，不需要再等新开发
- 它直接服务中国 POD 找款，不是纯技术演示
- 最容易验证“有没有真的省时间”
- 也最容易把平台反馈直接回流到项目判断里

## 输入

- 抖音链接
- 小红书链接
- 截图或商品图
- 评论区关键词
- 挂车 / 店铺 / 价格带信号
- 你自己的简短观察

## 处理

### 第一步

先进入 `00_收件箱`

当前实际做法：

- 飞书里发 `收件箱：...`
- `谋士` 直接生成一条 `00_收件箱` 笔记
- 笔记保留来源、时间、正文与简短说明

### 第二步

由 AI 助手把平台样本整理进监控口径：

- 平台是什么
- 发布时间或观察时间
- 互动数据大概怎样
- 图案 / 文案 / 情绪钩子是什么
- 有没有挂车、商品承接或价格线索
- 是否值得继续跟

当前标准：

- 还是平台样本、还在观察：先记进 [[20_项目/中国市场POD业务验证/14_中国市场_T恤样本采集记录表]]
- 已经形成题材判断：写入 [[20_项目/中国市场POD业务验证/12_中国市场_T恤平台找款与监控闭环]]
- 已经成为可复用规则：再提炼到 `40_知识库`

### 第三步

形成结构化输出：

- 候选题材
- 平台反馈强弱
- 哪类表达最容易被停留 / 收藏 / 评论
- 下一轮要继续监控的关键词
- 暂时不要做的方向

当前要求最小化为：

- 至少录入 `20` 条平台样本
- 至少得到 `1` 份监控汇总
- 至少输出 `1` 条候选题材方向
- 至少留下 `1` 条下一轮继续跟踪的监控关键词

## 输出

- 一份平台样本台账
- 一张项目内的监控与反馈页
- 一条候选题材判断
- 一组下一轮监控关键词

## 当前成功标准

本轮只要满足以下条件，就算这条链路验证成功：

1. 你能在飞书里稳定把素材送进 `00_收件箱`
2. 至少有 `1` 条平台样本被整理进 [[20_项目/中国市场POD业务验证/14_中国市场_T恤样本采集记录表]]
3. 至少有 `1` 轮监控判断被写进 [[20_项目/中国市场POD业务验证/12_中国市场_T恤平台找款与监控闭环]]
4. 最后能得到一份对中国 POD 有用的候选方向输出

## 当前不做的部分

这轮先明确不追求：

- 自动批量抓全网
- 自动做多平台分发
- 自动生成成品图
- 自动上架或自动运营
- 一次处理几十条来源
- 脱离抖音 / 小红书平台反馈单独拍题材

## 为什么先做这条

- 它贴近你真实业务目标
- 输入简单，今天就能开始
- 不依赖太多外部系统
- 能先把 OrbitOS 和 AI 整理流程跑通
- 题材反馈会更及时，不容易越做越脱离平台

## 暂时不做

- 自动批量抓取全网
- 自动生成成品图
- 自动上架
- 一次处理过多来源
