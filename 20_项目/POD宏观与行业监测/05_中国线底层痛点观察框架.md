# 中国线底层痛点观察框架

## 用途

这张页不是再讲一遍“退货率很重要”，而是把中国线真正该怎么盯底层痛点收成固定入口。

它回答的是：

- 中国线当前要去哪里看真实痛点
- 哪些信号只是噪音，哪些信号已经足够改产品线判断
- 底层痛点怎样回流到 `T恤` 产品线、平台监控页和宏观层

## 当前定位

这张页是 `04` 的中国线落地页，也是中国线样本回流的固定入口。

它不替代宏观层，而是把宏观层里那些“需要被真实样本验证的底层问题”收成动作。

## 当前判断

- 中国线不能只盯内容热度、挂车信号和物流总量
- 真正更该长期盯的是：`退货 / 退款 / 尺码 / 印花 / 履约 / 客服 / 差评结构`
- 邮政与快递总量只能证明“物流系统还在转”，不能证明这门生意做了以后不会被售后吃掉
- 如果同类痛点反复出现，它有资格直接改产品线判断，必要时还能往上推翻宏观层的乐观假设

## 观察顺序

默认不是先看“大盘”，而是先看真实摩擦。

`先看评论与售后反馈 -> 再看原因结构 -> 再判断是题材问题、产品问题，还是供应链问题 -> 再决定要不要继续放大`

一句话：

`先看为什么被退，后看还能不能放大。`

## 数据优先级

### A层：平台一手售后与评价

- 抖音商品评价、视频评论、直播评论、售后原因
- 小红书笔记评论、收藏语义、拔草反馈
- 淘宝 / 抖店 / 其他承接页的商品评价与追评

这是当前最该优先看的层，因为离真实下单与售后最近。

### B层：自有样本与测试记录

- 自己采集的找款样本
- 自己的出图与上架验证
- 后续真实订单、客服记录、退款原因

这层是以后最重要的“自有真相”来源。

### C层：公开投诉与外部吐槽

- 黑猫投诉等公开投诉平台
- 社交平台上的集中吐槽

这层适合补“结构性风险”，但不适合单独下结论。

### D层：行业与宏观辅助数据

- 邮政与快递量
- 行业报告
- 官方零售数据

这层只能辅助定方向，不能替代底层痛点观察。

## 当前最该盯的指标

### 1. 退货率 / 退款率

- 关注：
  - 哪类款退得快
  - 哪类题材热度高但退货也高
  - 哪个平台承接后退货更高

### 2. 退货原因结构

- 重点拆：
  - 尺码不合适
  - 面料 / 厚薄不符
  - 印花质感不符
  - 色差
  - 版型问题
  - 与内容预期不符

### 3. 尺码与版型稳定性

- 重点看：
  - 同版型不同批次是否稳定
  - 中性款 / 女款反馈差异
  - 评论区是否反复出现“偏大 / 偏小 / 肩窄 / 衣长不对”

### 4. 印花与洗后表现

- 重点看：
  - 掉色
  - 开裂
  - 发硬
  - 洗后图案变化

### 5. 履约与异常波动

- 重点看：
  - 节前延迟
  - 爆单延迟
  - 偏远地区异常
  - 售后处理中“物流慢”是否是高频原因

### 6. 客服摩擦与差评结构

- 重点看：
  - 售前高频提问
  - 售后争议点
  - 差评是否集中在少数几个结构性问题

### 7. 内容热而不转化

- 重点看：
  - 内容互动不错，但商品页评价差 / 退货高
  - 评论想买，实际承接差

## 预警规则

默认不要因为单条评论就推翻判断，先看是否重复。

- 同一问题只在单个样本出现：
  - 先记为局部噪音
- 同一问题在 `3` 个以上样本重复出现：
  - 升级为结构性问题候选
- 同一问题在 `2` 个以上平台都反复出现：
  - 升级为高优先级结构性问题
- 如果“内容好看但售后差”持续出现：
  - 可以直接下调这条产品线或题材的优先级

## 节奏与回流

- 周度：
  - 只服务当前活跃执行，更新样本记录
- 月度：
  - 汇总到产品线验证页，判断是否要改动作
- 季度：
  - 如果结构性问题持续存在，再回流到宏观与行业监测项目

默认回流顺序：

`样本记录 -> 产品线判断 -> 宏观支撑项目 -> 必要时改总项目`
