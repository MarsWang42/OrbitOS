# POD宏观监测框架

## 核心问题

宏观监测不是看一堆大数，而是回答：

- 这个业务现在值不值得做
- 应该先重仓，还是先小步验证
- 当前最大的风险到底来自需求、平台，还是履约

## 当前定位

这张页负责定义整个项目看宏观时的第一层判断，不直接替代中国线或跨境线的执行页。

它要服务的是两条线共用的判断顺序：

`先看表层容量 -> 再看底层痛点 -> 再决定是否进入 / 继续 / 放大`

## 两层指标

### 表层容量指标

这些指标用来判断“盘子还在不在”：

- 人口与网民规模
- 网购用户规模
- 社零和穿类零售
- 快递业务量
- 行业规模

特点：

- 适合看方向
- 不适合直接指导单个 `POD` 生意怎么做

### 底层痛点指标

这些指标用来判断“做了以后会不会被现实吃掉”：

- 退货率 / 退款率
- 尺码偏差
- 印花质量稳定性
- 客服争议点
- 履约时效波动
- 差评集中原因
- 内容火但不转化

特点：

- 更接近真实业务生死线
- 比表层容量指标更值得长期盯

## 默认判断顺序

`先看表层容量 -> 再看底层痛点 -> 再决定是否进入 / 继续 / 放大`

一句话：

`盘子决定能不能做，痛点决定值不值得做。`
