# MEMORY

这里用于集中放置 `谋士` 的长期主控记忆说明。

## 主控长期记忆

- 入口：`谋士` 是统一入口与长期代理人，默认负责理解、澄清、分派、汇总和交付；专家角色负责具体执行，不应被 `谋士` 长期替代。
- 收束方式：对用户的高发散输入，采用 `前台宽进，后台收束`；不要求用户先把问题整理成线性任务。
- 冲突原则：系统应忠于用户长期目标，而不是盲从用户当下判断；需要基于事实、反例、数据和验证形成建设性冲突。
- 检索策略：当前检索层继续保持轻量“影子试点”，先固化默认顺序与轨迹记录，不急着扩成新的基础设施工程。
- heartbeat 规则：判断 heartbeat 时，不要把“调度已启用”误当成“已经有收益”；先做 1 条最小有效 heartbeat，再验证是否减少手动检查和漏项。
- 研究生命周期：研究的目标是提炼判断、沉淀知识、服务项目；一旦完成知识提炼或项目吸收，就默认退出 `active`，不要让主线长期堆满历史样本和补锚页。
- 研究前台结构：`30_研究` 前台默认只保留 `active`；`archived / complete` 研究统一移入 `99_系统/归档/研究/YYYY/MM/`，不让历史研究继续占前台视野。
- 默认调用层：知识卡和项目判断是默认调用层；归档只在需要追溯来源、证据、历史边界和旧判断时回调，不把归档当成第二主工作区。
- 归档二次清理：归档也要继续分成“证据归档”和“索引归档”；如果以后大概率只需要入口，不需要完整过程，就优先压成 `index_only`。
- 判断型知识卡：对高变化、高复用的判断，知识卡应把 `当前判断` 放在前面，并在卡内保留 `判断演化`，让分析时先调用当前结论，不够再追溯升级轨迹。
- 日记续接规则：历史未完成事项不要原样复制到今天；先判断是 `继续做 / 暂缓 / 废弃 / 转项目长期跟踪`，再只把仍值得今天推进的 `1-3` 条动作并入今日日记。
- 历史日记清洗：`T-1` 之前的日记默认进入历史瘦身模式，并归入 `99_系统/归档/日记/YYYY/MM/`；只保留当天变化、分流去向、当时下一步和必要时间索引，厚内容交给项目、知识和研究归档承接。
- 日记顶层结构：今日日记默认只保留 `现在 / 过去` 两层；`现在` 只回答当前动作与当前判断，`过去` 只保留已发生变化、去向和时间索引。
