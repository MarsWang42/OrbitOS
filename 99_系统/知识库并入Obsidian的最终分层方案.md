# 知识库并入 Obsidian 的最终分层方案

## 相关规则

- [[99_系统导航索引]]
- [[30_研究与40_知识库的边界与命名规范]]
- [[00_收件箱的处理规范]]

## 结论

这套系统以后统一以 Obsidian Vault 作为唯一知识与工作主空间。

原则是：

- 用户知识、项目、研究、任务都放在 Obsidian 主结构里
- OpenClaw 的角色工作区也放在 Obsidian 里
- `~/.openclaw` 只保留运行配置、agent 状态、日志和归档
- 不再维护一套平行知识库

## 总体分层

### 1. 收件层

- 目录：`00_收件箱`
- 用途：临时捕获、待分类输入、尚未决定归属的内容
- 进入条件：
  - 用户随手一提
  - 还不能判断该进项目、研究还是知识库
  - 需要后续整理

### 2. 日常推进层

- 目录：`10_日记`
- 用途：每日计划、复盘、推进记录、当天上下文
- 进入条件：
  - 当天发生的事
  - 与某项目推进有关的记录
  - `/start-my-day` 的输出

### 3. 执行层

- 目录：`20_项目`
- 用途：需要持续推进的事项
- 进入条件：
  - 有明确目标
  - 不是一次性回答
  - 需要阶段、任务或进展追踪

项目规则：

- 简单项目可用单文件
- 复杂项目可用文件夹
- frontmatter 统一保留：
  - `type: project`
  - `status: active|on-hold|done`
  - `area: "[[AreaName]]"`

### 4. 研究层

- 目录：`30_研究`
- 用途：可复用的主题研究、行业分析、框架整理
- 进入条件：
  - 不是只服务一次任务
  - 后续可能被多个项目复用
  - 包含样本、对比、推断、限制

### 5. 原子知识层

- 目录：`40_知识库`
- 用途：概念、原则、方法、模型等原子知识
- 进入条件：
  - 可以被压缩成一个概念或一条方法
  - 适合被多个笔记双链引用
  - 更像知识卡片，而不是研究报告

### 6. 资源层

- 目录：`50_资源`
- 用途：外部素材、截图、内容汇总、精选资源
- 进入条件：
  - 更偏素材保存
  - 更偏资源归档
  - 不适合直接当作知识卡片

### 7. 计划层

- 目录：`90_计划`
- 用途：阶段性执行方案、推进计划、行动清单
- 进入条件：
  - 需要一个相对独立的执行方案
  - 会在完成后归档

### 8. 系统层

- 目录：`99_系统`
- 用途：模板、提示词、数据库、归档、系统说明
- 进入条件：
  - 属于系统规则而不是业务内容
  - 属于长期配置或模板

### 9. Agent 工作层

- 目录：`OpenClaw配置/05_角色工作区`
- 用途：OpenClaw 各角色的工作规则、身份说明、运行上下文
- 进入条件：
  - 属于 Agent 自身的行为规则
  - 属于角色内部工作说明
  - 不属于用户知识主结构

## 什么内容不要放进角色工作区

以下内容应优先进入 OrbitOS 主结构，而不是 `OpenClaw配置/05_角色工作区`：

- 正式项目内容
- 用户要长期保留的研究笔记
- 原子知识卡片
- 正式资源归档
- 长期系统模板

角色工作区更适合放：

- `SOUL.md`
- `AGENTS.md`
- `USER.md`
- `TOOLS.md`
- `HEARTBEAT.md`
- 角色内部约束与工作说明

## 推荐流转规则

默认内容流转：

`收件箱 -> 项目/研究/知识库/资源 -> 日记关联 -> 必要时归档`

默认协作流转：

`用户 -> 谋士 -> 专家角色 -> 审核 -> 用户确认`

## 判断口诀

可以用这组简单判断：

- 不确定放哪：先进 `00_收件箱`
- 要持续推进：进 `20_项目`
- 要系统整理主题：进 `30_研究`
- 要沉淀成单点知识：进 `40_知识库`
- 只是素材与收集：进 `50_资源`
- 是规则和模板：进 `99_系统`
- 是 Agent 自己的运行规则：进 `OpenClaw配置/05_角色工作区`

补充边界：

- 全局通用模板：进 `99_系统/模板`
- 只服务某条业务线的专用模板：进对应项目

## 与 OpenClaw 的关系

当前结构已经是：

- `谋士` 直接使用整个 Vault 根目录作为主控工作区
- 专家角色使用 `OpenClaw配置/05_角色工作区`
- `~/.openclaw` 只保留运行态内容

这意味着：

- 用户看到的知识结构
- Obsidian 里的知识结构
- OpenClaw 实际工作的知识结构

现在已经基本统一。
