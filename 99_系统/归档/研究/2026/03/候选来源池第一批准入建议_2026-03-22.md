# 候选来源池第一批准入建议

## 一句话结论

围绕 `OpenClaw + Obsidian` 的现有研究方向，下一批最值得纳入候选来源池的，不是再扩一个同类短视频平台，而是先补两类官方结构化一手源：

1. `OpenClaw GitHub Releases API`
2. `Obsidian Changelog RSS`

这样做的价值是：更新信号更稳、字段更结构化、自动化成本更低，也更适合回写到 `30_研究 / 20_项目 / 今日日记`。

## 为什么选这两个

### 1. OpenClaw 侧优先补 GitHub Releases

- GitHub 官方文档明确提供 `releases` 与 `releases/latest` 接口
- 对公开仓库可直接读取，不要求先登录
- 返回的是结构化发布信息，天然适合做：
  - 版本变更追踪
  - 新能力发现
  - 项目级升级判断

这比继续堆同类二手解读视频更适合作为“正式候选来源”。

### 2. Obsidian 侧优先补 Changelog RSS

- Obsidian 官方 changelog 页明确提供 `RSS`
- changelog 本身就是官方更新入口
- 内容粒度稳定，适合持续监听：
  - 新功能
  - 破坏性变化
  - 自动化相关能力

尤其对当前方向很关键，因为 `2026-02-27` 的官方 changelog 已明确发布 `Obsidian CLI`，这直接关系到后续 `OpenClaw -> Obsidian` 自动化链路。

## 当前准入标准

这两个来源之所以可以进第一批候选池，是因为同时满足：

- 一手来源：来自官方站点或官方平台
- 结构化：可稳定拿到发布时间、版本、正文或字段
- 低维护：不依赖手工刷视频或强登录态
- 高相关：直接服务 `OpenClaw / Obsidian` 主方向
- 易回链：适合沉淀为研究、项目动作或知识更新

## 当前不优先扩什么

当前不优先继续扩更多“同类内容平台”，例如再去补一个新的短视频或社区平台，原因是：

- 现有 `B站 / YouTube / 抖音` 已足够承担发现与样本补锚
- 当前更缺“官方更新入口”，而不是“更多分发平台”
- 如果先扩同类平台，只会继续放大获取链路复杂度

## 可执行动作

### A. OpenClaw

- 候选源：`https://api.github.com/repos/openclaw/openclaw/releases/latest`
- 用途：追踪新版本、新功能、破坏性变化
- 建议状态：进入候选来源池，后续再决定是否升为正式订阅

### B. Obsidian

- 候选源：`https://obsidian.md/changelog`
- 用途：追踪官方 changelog 与 RSS 更新
- 建议状态：进入候选来源池，优先关注自动化、CLI、插件与同步相关更新

## 这次形成的可验证结论

第一批来源池扩容应优先补“官方结构化更新源”，而不是继续扩“内容分发平台”。  
对当前系统，最先纳入候选池的两个入口是：

- `OpenClaw GitHub Releases API`
- `Obsidian Changelog RSS`
