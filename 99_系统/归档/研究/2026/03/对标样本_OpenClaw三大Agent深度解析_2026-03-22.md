# 对标样本：OpenClaw三大Agent深度解析

## 基本信息

- 主题：OpenClaw 三大 Agent 的能力拆分与使用场景
- 平台：B站
- 样本名称：OpenClaw三大Agent深度解析
- 样本类型：参考样本
- 样本链接：https://b23.tv/UhjCnFA
- 记录日期：2026-03-22

## 为什么选它做对标

- 我当前要解决的问题是什么：
  - 给自己的 OpenClaw + Obsidian 系统建立更清晰的多 Agent 分工和知识流转链
- 这个样本为什么值得参照：
  - 它把 Persistent Agent、Sub-Agent、ACP Agent 三类能力拆得比较清楚，也给了实操场景
- 它最值得看的地方是什么：
  - 把“不同 Agent 形态适合什么任务”讲清楚，而不是只讲抽象概念
- 它最不该被直接照搬的地方是什么：
  - 它更偏产品能力演示，不包含你当前系统里最重的知识治理、复盘和审查闭环

## 样本概况

- 它主要在做什么：
  - 用教程视频方式讲解 OpenClaw 三类 Agent 的定义、差异和实战场景
- 它处在什么阶段：
  - 更像社区教学与能力展示阶段
- 它的目标人群是谁：
  - 想快速理解 OpenClaw 多 Agent 结构的用户
- 它依赖的关键资源是什么：
  - 产品本体能力、演示案例、教程表达清晰度
- 它当前最明显的优势是什么：
  - 概念拆分清晰，适合作为初始参照系

## 共性与差异

- 它和我当前目标最相似的地方：
  - 都在解决“不同 Agent 做不同事”的问题
  - 都强调按任务特点选择不同执行主体
- 它和我当前目标差异最大的地方：
  - 它更偏 Agent 类型能力介绍
  - 你当前系统更偏“飞书入口 -> 分工执行 -> 审核复盘 -> Obsidian 沉淀”的完整工作流
- 哪些差异会直接影响结果：
  - 如果只按视频讲的 Agent 类型理解，很容易忽略知识沉淀、验证和角色边界
- 哪些差异暂时可以忽略：
  - 视频中的具体演示界面和单次操作细节

## 成功或失败机制判断

- 它为什么会成功：
  - 概念边界清楚，示例直观，能降低理解门槛
- 它为什么可能失败：
  - 如果把视频内容当最终方案，可能会忽略后续治理和验证成本
- 哪些部分更像规律：
  - 不同任务确实适合不同 Agent 形态
  - 分工越清楚，系统越不容易混乱
- 哪些部分更像阶段性现象：
  - 具体产品演示方式和当前社区最佳实践可能会变化

## 可借鉴与不可照搬

- 最值得借鉴的做法：
  - 先按任务性质拆分角色，而不是让一个 Agent 什么都做
  - 在复杂任务上明确主控、执行、审核的不同职责
- 可以借鉴但要改造的做法：
  - Agent 类型选择逻辑
  - 需要结合你的知识库、收件箱、研究和审核流程重新落地
- 明确不应直接照搬的做法：
  - 只模仿产品演示，不补知识沉淀、日记追溯、自审和他审
