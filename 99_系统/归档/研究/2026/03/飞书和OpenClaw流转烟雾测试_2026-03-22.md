# 飞书和OpenClaw流转烟雾测试

## 基本信息

- 主题：飞书与 OpenClaw 信息流转基础验证
- 日期：2026-03-22
- 来源：飞书直接输入

## 测试内容

本次测试了飞书与 OpenClaw 的基础流转能力：

### 1. 触发词路由 ✅

| 触发词 | 预期行为 | 状态 |
|--------|---------|------|
| `收件箱：` | 创建收件箱笔记 | ✅ |
| `项目：` | 落入 20_项目 | ✅ |
| `研究：` | 落入 30_研究 | ✅ |
| `知识：` | 落入 40_知识库 | ✅ |
| 无前缀链接学习 | 落入 30_研究 + 链接学习记录 | ✅ |

### 2. 链接学习 ✅

| 来源 | 抓取能力 | 状态 |
|------|---------|------|
| B站 | 可直接抓取摘要 | ✅ |
| 抖音 | 平台限制，无法直接抓取 | ⚠️ 需替代方案 |

### 3. 桌面操作 ✅

| 操作 | 工具 | 状态 |
|------|------|------|
| 截图 | screencapture | ✅ 需 node 屏幕录制权限 |
| 图像识别 | AI 图像模型 | ✅ |
| 鼠标点击 | cliclick | ✅ |
| 应用启动/关闭 | open/pkill | ✅ |
| 播放/暂停 | 截图定位 + cliclick | ✅ 已验证网易云音乐 |

### 4. 权限发现

- OpenClaw Gateway 是后台服务（node 进程）
- 屏幕录制权限需在"隐私与安全性"中把 `node` 加入白名单
- 截图权限与普通 App 授权方式相同，但入口在"屏幕录制"

### 5. 知识沉淀规则 ✅

- 正式落位后必须同步到今日日记
- 链接学习记录同步到 `OpenClaw配置/02_任务管理/链接学习/`
- 临时截图使用后及时清理

## 核心结论

飞书 -> OpenClaw -> Obsidian 的基础流转链路已验证可用，核心障碍是抖音平台无法直接抓取内容。

## 待改进

- 抖音链接的替代抓取方案（需用户手动提供内容或找 B站/YouTube 同主题版本）
- 网易云音乐播放控制的稳定坐标（当前为 500,755，可能因窗口大小变化）
