# OpenViking最适合替代哪一层

## 一句话结论

如果你后面真的要局部试点 `OpenViking`，最适合先替代的不是 `Obsidian` 的显性知识层，也不是整套记忆层，而是 **检索层**；第二顺位才是 **资源层**。  

## 最终排序

| 排名 | 层级 | 是否适合先替代 | 判断 |
|---|---|---|---|
| 1 | 检索层 | 是 | 最适合先试点 |
| 2 | 资源层 | 条件适合时可试 | 第二顺位 |
| 3 | 记忆层 | 暂不建议先动 | 风险偏高 |
| 4 | 技能层 | 暂不建议先动 | 当前收益不够大 |
| 5 | 显性知识层 | 不应替代 | 继续以 Obsidian 为主 |

## 为什么最适合先动检索层

`OpenViking` 最强的地方，不是“你终于有个更酷的知识库”，而是：

- 目录递归检索
- 语义检索
- 分层加载
- 检索轨迹可观测

这些能力天然更像“检索层升级”，而不是“知识库替换”。

你现在这套系统里，最容易变重、变乱、变得不好追踪的地方，恰恰也是检索：

- 链接学习补锚
- 研究 / 资源 / 技能跨层跳转
- 记忆、知识、资源怎么被角色读取
- 为什么这次命中了这条信息、没命中那条信息

所以如果只选一层先试，它最适合补的是：

`让上下文怎么被找到、怎么被加载、为什么被找到，变得更清楚。`

## 为什么资源层排第二

资源层和 OpenViking 也非常像，因为它把 `resources` 视为上下文系统的一部分。

你现在的资源层主要分散在：

- `30_研究`
- `50_资源`
- 链接学习记录
- 对标样本
- 多模态样本

这层后面确实有可能被 `OpenViking` 明显增强，但它仍然依赖一个更稳的检索层来支撑。  
所以更合理的顺序是：

`先试检索 -> 再看资源`

## 为什么不建议先动记忆层

虽然 `OpenViking` 对记忆层也很强，但你现在的记忆层还和这些东西绑得很紧：

- `memory-lancedb`
- 角色摘录
- 日记流转
- 复盘更新

这层一旦先动，容易同时冲击：

- 你现有的行为习惯
- 角色经验沉淀
- 会话记忆治理
- 运行时稳定性

也就是说，它不是不能碰，而是：

`现在先碰记忆层，改动面太大，收益不如先从检索层开始更稳。`

## 为什么不建议先动技能层

你现在的技能层已经有：

- `Skills`
- `SOP`
- `模板`
- `角色知识摘录`

它们的主要问题不是“完全没有组织”，而是后续还可以更统一治理。  
但这件事短期不会像检索层那样马上带来可感知提升。

所以技能层更适合：

- 在检索层和资源层更稳之后
- 再考虑是否统一到更底层的上下文基础设施里

## 为什么显性知识层不该替代

这一点最明确：

- `Obsidian`
  - 是你的人类知识底座
  - 负责阅读、复盘、表达、追溯、项目推进
- `OpenViking`
  - 更适合 Agent 在运行时组织和调用上下文

所以这层不只是“不建议现在替代”，而是：

`不应该把它当替代对象。`

## 最小试点建议

如果后面真的要做局部试点，最小范围建议是：

### 试点目标

只试 `检索层`

### 试点范围

- 不碰 `00_收件箱 / 30_研究 / 40_知识库` 的主结构
- 不碰今日日记和项目流转
- 只试：
  - 角色如何读取资源
  - 如何做分层加载
  - 如何记录检索轨迹

### 成功信号

- 找资料更快
- 命中更准
- 为什么命中这条内容更可解释
- 不会破坏你现有 Obsidian 主流程

### 失败信号

- 只是多了一套重系统，但没有明显提升
- 反而让当前链路更难维护
- 让知识沉淀和运行时上下文混在一起

## 当前最推荐的动作

现在最好的选择不是安装，而是：

1. [x] 把“你当前检索层”单独画出来
2. [x] 标出它现在最痛的 3 个点
3. [x] 用 `OpenViking` 的能力去一一映射，看它能补哪些、补不到哪些
4. [ ] 用 3 条真实检索轨迹，判断它是否值得进入最小试点

## 当前结论

- `OpenViking` 最适合先替代的是：`检索层`
- 第二顺位：`资源层`
- 现在不建议先动：`记忆层 / 技能层`
- 不应替代：`Obsidian` 显性知识层
