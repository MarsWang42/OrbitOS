# 当前系统 vs OpenViking 对照表

## 一句话结论

你现在这套 `OpenClaw + Obsidian + 记忆层 + 角色层`，本质上已经在手工实现一套 Agent 上下文系统；`OpenViking` 更像把这件事做成统一基础设施。它最适合补的是“统一上下文治理”和“运行时上下文管理”，不适合直接替掉你的显性知识沉淀系统。

## 总体判断

| 维度 | 你当前系统 | OpenViking | 当前判断 |
|---|---|---|---|
| 人类知识沉淀 | 强 | 弱 | 继续以 Obsidian 为主 |
| Agent 运行时上下文 | 中 | 强 | OpenViking 更有优势 |
| 记忆 / 资源 / 技能统一治理 | 中 | 强 | OpenViking 最值得借鉴 |
| 可追溯与日记流转 | 强 | 中 | 你当前系统更贴近你的工作方式 |
| 轻量可控性 | 强 | 中 | 当前系统更轻、更可渐进演化 |
| 基础设施完整度 | 中 | 强 | OpenViking 更像下一阶段底层 |

## 分层对照

### 1. 显性知识层

你当前系统：

- `00_收件箱`
- `30_研究`
- `40_知识库`
- `10_日记`
- `20_项目`

OpenViking：

- 不以“人类可读知识库”为主目标
- 更偏 Agent 的上下文存储和调用

判断：

- 这层不该被 OpenViking 取代
- `Obsidian` 仍然是你最核心的显性知识底座

### 2. 记忆层

你当前系统：

- `memory-lancedb`
- 角色摘录
- 对话蒸馏
- 日记流转和复盘

OpenViking：

- 把记忆视为上下文系统的一部分
- 更强调长期自迭代和统一上下文管理

判断：

- 这层是最值得对标的
- 但你现在还不需要立刻替换，先借它的治理思路更划算

### 3. 资源层

你当前系统：

- `30_研究`
- `50_资源`
- 链接学习记录
- 对标样本 / 多模态样本

OpenViking：

- 直接把 resources 纳入统一上下文系统
- 更强调 Agent 可直接读取和递归检索

判断：

- 这层和你最像
- 也是后面最可能被 OpenViking 明显增强的一层

### 4. 技能层

你当前系统：

- `Skills`
- `SOP`
- `角色知识摘录`
- `模板`

OpenViking：

- 把 skills 作为上下文系统组成部分统一管理

判断：

- 这层和你现有设计高度同构
- 最值得借鉴的是“不要把 skill 当成散落附件，而要当统一上下文资产”

### 5. 检索层

你当前系统：

- 搜索定锚
- 推荐扩展
- GEO 适配
- 手工补锚
- 部分记忆召回

OpenViking：

- 目录递归检索
- 语义检索
- 分层加载
- 检索轨迹可观测

判断：

- 这层是它相对你现在更强的地方
- 尤其“检索轨迹可观测”很值得你后续借鉴

## 最值得借鉴的点

### 1. 统一上下文视角

你现在已经分出了很多层，但更多还是“按目录和工作习惯治理”。OpenViking 的启发是：把这些层明确看成同一套上下文系统。

### 2. 分层加载

这和你现在的 `标题级 / 摘要级 / 片段级 / 全量级 / 实操级` 非常适合映射。

### 3. 检索可观测

你已经非常重视“可追溯”，OpenViking 的检索轨迹观测能力，正好和你的日记流转、复盘体系相呼应。

### 4. Agent 做事经验也属于上下文

这和你现在做的“角色摘录 -> 知识卡 -> 复盘更新”高度一致。

## 当前不适合马上做的事

- 不适合现在就迁移整个系统
- 不适合在当前默认学习流还没彻底跑稳前，再引入一个更重的底层
- 不适合把 Obsidian 的显性知识组织逻辑迁到 OpenViking

## 当前最适合做的事

### 路线 A：只借设计，不接入

适合现在。

做法：

- 借它统一 `记忆 / 资源 / 技能` 的视角
- 借它分层加载和可观测检索的思路
- 继续在现有系统里迭代

### 路线 B：局部试点

适合下一阶段。

做法：

- 先只选一层做试点
- 比如把 `角色经验 + 技能 + 资源` 做一个小范围上下文实验
- 不碰主知识库

### 路线 C：底层升级

现在还不建议。

做法：

- 等你现有链路足够稳定，再考虑把 OpenViking 当“下一代上下文底层”

## 当前建议

如果按投入产出比排序：

1. 先继续把现有默认学习流跑稳
2. 先把 `记忆 / 资源 / 技能` 三层关系画清楚
3. 先借 OpenViking 的治理思路，不急着安装
4. 等候选来源池、默认补锚和学习深度升级都稳定后，再评估局部试点

## 当前结论

- `OpenViking` 对你不是“马上替换”，而是“下一阶段底层设计参考”
- 你现在最该拿走的是它的结构思维，不是立刻把系统迁过去
- 它最可能补强你的，是：
  - 统一上下文治理
  - 分层加载
  - 检索可观测
  - 记忆自迭代
