# 视频内容获取方法与学习深度升级

## 一句话结论

当前真正的卡点不是“某一个平台完全没有工具”，而是“跨平台还没有统一成 `先判平台 -> 走平台最优链路 -> 通用兜底 -> 学习深度升级 -> 验证` 的默认工作流”。

## 先分清两层

这篇里有两层东西，不能混着看：

- `通用逻辑`
  - 先判断平台
  - 先走平台最优链路
  - 原链接受阻时去主来源平台定向补锚
  - 通过验证持续扩容渠道池
- `当前方案`
  - B站优先 `yt-dlp`
  - YouTube 先试 `yt-dlp` 元信息 + 字幕；受阻时先停在元信息 / 轨道确认层，并转人工片段验证
  - 抖音优先 `douyin-mcp-server`

前者相对稳定，后者后面完全可能被更优方案替换。

## 现在卡在哪里

### 1. 不是工具空白

根据 [[99_系统/当前已接入平台清单]]：

- B站：
  - `yt-dlp` 已完成真实视频读取验证
- YouTube：
  - 搜索层可用
  - 但正式 `watch` 链接的深取仍可能被 anti-bot 挡住
- 抖音：
  - 已完成部分公开视频解析与无水印链接获取验证
  - 但部分分享链仍要求 `fresh cookies`

所以“平台完全拿不到内容”并不是当前主卡点。

### 2. 真正卡点是工作流没有接通

现在更大的问题是：

- 丢了视频链接进来
- 系统常常只生成标题级或摘要级研究页
- 没有稳定把可用工具自动用在：
  - 拉正文
  - 拉字幕
  - 拉关键片段
  - 然后把 `learning_depth` 往上提

也就是说，卡点不在“有没有锤子”，而在“锤子没有自动进入这条生产线”。

### 2.5 还存在平台级访问前提

以抖音为例，最新这条分享链在 `yt-dlp --dump-json --skip-download` 下直接报：

- `Fresh cookies (not necessarily logged in) are needed`

这说明有些平台不是“完全不能抓”，而是“默认匿名链路不稳定”，还需要把 cookies、登录态、分享链类型一起纳入获取策略。

### 2.8 还要区分平台最优链路和通用链路

最新这条抖音样例同时证明了两件事：

- `yt-dlp` 匿名抓取这条分享链会报 `Fresh cookies (not necessarily logged in) are needed`
- 但 `douyin-mcp-server` 这条专用链路却能成功返回：
  - `video_id`
  - 标题
  - 无水印下载链接

这说明真正应该统一的不是“哪个平台能不能读”，而是：

`先判平台 -> 先试平台最优链路 -> 再试通用链路 -> 再补 cookies / 登录态`

### 3. 第二层卡点是验证链还没接上

即使拿到了内容，也还要继续回答：

- 这条内容是不是你当前阶段最适合的？
- 它是不是和现有内容重复？
- 它能不能转成真实测试，而不是只停在学习记录？

## 现在最适合围绕哪个卡点突破

最值的突破口只有一个：

`把跨平台内容获取能力接成默认动作`

也就是：

`视频链接 -> 自动识别平台 -> 自动尝试平台最优链路 -> 自动补通用兜底 -> 自动标学习深度 -> 再决定是线索、研究草稿还是深度研究`

## 为什么先攻这个点

- 这是后面一切升级的前置条件
- 不解决它，你会不断卡在 `标题级 / 摘要级`
- 解决它之后：
  - 对标判断会更准
  - 多模态记录会更实
  - 验证清单也更容易生成

## 当前样例证明

- [[99_系统/归档/研究/2026/03/OpenClaw零基础系统教程_2026-03-22]]
  - 当前已从 `标题级` 升到 `摘要级`
  - 已证明 B站 可以先靠标题、UP 主、时长、章节把研究抬到可用层
- [[99_系统/归档/研究/2026/03/OpenClaw三大Agent深度解析_2026-03-22]]
  - 目前是 `摘要级`
  - 已有摘要与时间戳，但还没升到全量级

这说明现在最缺的不是“再多收几个视频”，而是“把跨平台内容获取能力接稳”。

- [[99_系统/归档/研究/2026/03/GitHub一周热点第107期_2026-03-22]]
  - 当前仍是 `标题级`
  - 但已经证明抖音不能只看 `yt-dlp`
  - 应先走 `douyin-mcp-server` 这类平台专用链路

## 最新真实验证：B站默认动作 v1

这轮我直接拿 [[99_系统/归档/研究/2026/03/OpenClaw零基础系统教程_2026-03-22]] 做了本机验证，使用的是：

- `yt-dlp 2026.03.03`
- 样本链接：`https://b23.tv/lpIKSwU`

### 当前已确认

- 匿名 `yt-dlp -J --no-playlist --skip-download` 已能稳定做到：
  - 解析 `b23.tv` 短链到正式 `BV` 视频
  - 拿到标题、UP 主、时长
  - 拿到章节 / 时间戳结构
- 本次样本实际拿到的结构化信息包括：
  - 视频标题：`小白到高手！零基础OpenClaw系统教程：安装、实操、降本、AI团队搭建！`
  - UP 主：`木子不写代码`
  - 时长：约 `52:58`
  - 章节数：`7`
- `yt-dlp --list-subs` 明确提示：
  - B站正常字幕需要登录态
  - 匿名情况下这条样本只显示 `danmaku xml`
- `--cookies-from-browser chrome` 在这条样本上仍未返回正常字幕

### 当前最重要的收口

- 对 B站 来说，当前默认动作不该写成“先拿字幕”
- 更稳的写法应该是：
  1. 先用 `yt-dlp` 匿名拿标题、UP 主、时长、章节
  2. 先把研究页从 `标题级` 升到 `摘要级`
  3. 只有当章节结构仍不够支撑判断时，再追加 cookies、登录态或手动看片段
- 也就是说：
  - **章节 / 时间戳是默认可期待产物**
  - **字幕是加分项，不是默认门槛**

## 最新真实验证：抖音默认动作 v1

这轮直接拿 [[99_系统/归档/研究/2026/03/GitHub一周热点第107期_2026-03-22]] 的备用分享链做复核，样本是：

- `https://v.douyin.com/YPG-UT71Ajc/`

### 当前已确认

- 通用链路 `yt-dlp -J --skip-download --no-playlist` 对这条分享链返回：
  - `ERROR: [Douyin] 7619589170553539886: Fresh cookies (not necessarily logged in) are needed`
- 平台最优链路 `douyin.parse_douyin_video_info` 对同一条分享链成功返回：
  - `video_id: 7619589170553539886`
  - 标题：`GitHub 一周热点第107期 ...`
  - `download_url`
- 也就是说：
  - 抖音不是“默认拿不到”
  - 而是**匿名通用链路不稳定，平台专用链路优先级更高**

### 当前最重要的收口

- 对抖音来说，当前默认动作不该写成“先试 `yt-dlp`”
- 更稳的写法应该是：
  1. 先判定为抖音分享链
  2. 先走 `douyin-mcp-server`
  3. 先拿标题、`video_id`、下载链接，把线索从 `标题级` 抬到 `摘要级`
  4. 只有当结构化标题仍不足以支持判断时，再补 `yt-dlp`、fresh cookies、网页登录态或手动查看
- 也就是说：
  - **平台最优链路是默认动作**
  - **通用链路是第二层兜底，不是第一步**

## 最新真实验证：YouTube 当前边界

这轮我自己从 `ytsearch5:OpenClaw tutorial` 里选了一条真实样本：

- 标题：`OpenClaw Tutorial for Beginners - Crash Course`
- 频道：`Adrian Twarog`
- 时长：`7:58`
- 链接：`https://www.youtube.com/watch?v=u4ydH-QvPeg`

### 当前已确认

- `yt-dlp --flat-playlist` 的搜索层能稳定拿到：
  - 标题
  - 频道
  - 时长
  - 正式 `watch` 链接
- 但对这条正式 `watch` 链接继续执行：
  - `yt-dlp -J --skip-download --no-playlist`
  - `yt-dlp --list-subs --no-playlist`
  - `yt-dlp --cookies-from-browser chrome ...`
  都仍然返回：
  - `Sign in to confirm you’re not a bot`
- 继续补的非 `yt-dlp` 路径 `youtube-transcript-api 1.2.4` 对同一条视频返回：
  - `RequestBlocked`
  - 原因指向：当前 IP 被 YouTube 阻断
- 另外，本机 `yt-dlp 2026.3.3` 的 `--impersonate chrome` 当前也不可用：
  - `Impersonate target "chrome" is not available`
  - 原因是缺少对应 `curl_cffi` 支持
- 再往前推的 browser 方案这轮也已补到更具体边界：
  - 已登录页面源码里能直接看到 `captionTracks`
  - 当前样本存在 `1` 条轨道：`英语 (自动生成)`
  - 但对该轨道的 `timedtext` 请求当前返回 `200` + 空正文
  - 即使追加 `fmt=json3` 也仍为空体

### 当前最重要的收口

- 对 YouTube 来说，当前默认动作不该再写成“元信息 + 字幕稳定可得”
- 更稳的写法应该是：
  1. 先用 `yt-dlp` 搜索或直链尝试获取元信息和字幕
  2. 如果命中 anti-bot，就不要把它误判成“这条视频不值得学”
  3. 不要默认指望 `youtube-transcript-api` 一定能救场，因为当前 IP 也可能被挡
  4. browser 方案可以先确认字幕轨道是否存在，但当前仍未证明能稳定拿到字幕正文
  5. 在当前环境里，不默认继续上代理；到这一步直接转手动看片段验证
- 也就是说：
  - **`yt-dlp` 仍是第一尝试**
  - **`字幕` 不是当前可默认承诺的产物**
  - **当前 browser 方案已能看到轨道，但还没拿到正文**
  - **YouTube 当前默认收口应是：受阻时转人工片段验证，不默认上代理**

## 推荐突破路径

### 第一阶段：打通获取

先统一成一套跨平台顺序：

1. 识别平台
2. 优先走平台最优链路
3. 再走通用链路
4. 再补 cookies / 登录态 / 权限
5. 如果原链接仍受阻，再带着标题 / 主题 / 作者 / 项目名去主来源平台定向补锚
6. 最后才手动兜底

- B站：
  - 优先 `yt-dlp` 匿名拿标题、UP 主、时长、章节
  - 先用章节把研究页从 `标题级` 升到 `摘要级`
  - 如果仍不够，再看字幕、描述、cookies 和手动片段验证
- YouTube：
  - 先试 `yt-dlp` 元信息 + 字幕
  - 如果被 anti-bot 挡住，先补 cookies / browser 轨道确认
  - 仍拿不到正文时，直接转手动片段验证
- 抖音：
  - 优先 `douyin-mcp-server`
  - 再补 `yt-dlp`、fresh cookies、网页登录态

### 第二阶段：打通升级

- 获取成功后，自动把 `learning_depth` 从：
  - `标题级` 提升到 `摘要级 / 片段级 / 全量级`

### 第三阶段：打通验证

- 拿到正文后，自动回答：
  - 这是不是重复内容
  - 这是不是更适合当前阶段
  - 这条能不能转成真实测试

## 最小验证建议

 最先做的不是全平台通吃，而是：

1. [x] 用一条 B站视频验证“能不能稳定拿到更深内容”
2. [x] 成功后，把对应研究页从 `标题级` 升到 `摘要级 / 片段级`
3. [x] 再把其中 `1` 个点转成真实测试任务

## 当前默认动作 v1

如果后面再来 `B站 / YouTube / 抖音` 视频链接，当前最稳的默认顺序先写成这样：

1. 先判平台
2. 先走平台最优链路
3. 优先拿“足够把 `标题级` 升到 `摘要级`”的最小结构化信息
4. 字幕 / 全文 / 关键片段作为第二层增强，不再默认假设第一步就能拿到
5. 只在需要更深判断时，再补 cookies、登录态、主来源补锚和手动验证

当前这版已经有两条真实样本支撑：

- `B站 -> yt-dlp 匿名拿结构化信息 -> 升到摘要级`
- `抖音 -> douyin-mcp-server 优先 -> 再按需补通用兜底`
- `YouTube -> 先试 yt-dlp 元信息 / 字幕 -> 再试 transcript API -> 再看 browser 是否能确认轨道 -> 仍无正文时直接转人工片段验证`
