# TikTok POD通用业务框架

## 来源

基于旧资料《1.3-tk汇报材料.pptx》提炼。原始资料里有大量特定国家、特定类目、特定阶段的数据，本笔记只保留可复用的方法框架。

## 这份旧资料里真正可复用的部分

### 1. 先讲战略意图

不要一上来讲执行动作，先讲清楚：

- 为什么做这个业务
- 要打造什么样的品牌或项目
- 短期与中长期目标分别是什么

### 2. 先回答“为什么是 TikTok”

旧资料的核心判断可以抽象成一句话：

> TikTok 更适合用内容先圈人、再转化，而不是只做传统货架电商式卖货。

对 POD 来说，这意味着：

- 不是只找低价款
- 而是要找到“什么内容能带来兴趣和转化”

### 3. 市场选择要看 3 类维度

- 市场规模与增长潜力
- 用户在 TikTok 上的购物渗透度
- 起量难易度与竞争环境

旧资料里写的是东南亚国家筛选，这一层现在可以通用成任何目标市场判断框架。

### 4. 类目选择要看 6 类维度

- 市场容量
- 增长速度
- 认证门槛
- 研发壁垒
- 品牌依赖度
- 市场介入难度

对 POD 来说，可以转译成：

- 题材容量够不够大
- 同质化是不是太严重
- 视觉差异化空间大不大
- 是否容易形成系列内容和系列产品

### 5. 产品策略本质上是“品牌表达”

旧资料不是单纯讲爆品，而是在讲：

- 什么样的产品适合承载品牌理念
- 什么样的内容能把品牌理念讲出来
- 什么样的视觉和卖点更适合持续放大

这点对 POD 特别重要，因为 POD 很容易陷入只换图、不成体系的问题。

### 6. 短期策略要按阶段拆

旧资料最有价值的地方之一，是把 0-3 个月拆成：

- 选品 / 测品
- 内容测试
- 打品
- 放量
- 盈利模型验证

如果换成 POD 语言，可以理解为：

- 题材测试
- 设计方向测试
- 内容表达测试
- 链接验证
- 复用与复制

### 7. 运营不是一个岗位的事，而是一套链路

旧资料把内容、达人、投流、店铺、客服、采购、法务、物流都串起来了。可抽象成一条通用链路：

市场洞察 -> 选题/选品 -> 内容表达 -> 流量获取 -> 转化 -> 复盘 -> 复制

### 8. 最后一定要落到经营模型

旧资料后半段大量是：

- 团队配置
- 物流仓储
- 现金流
- 年度销售额
- 利润率

这说明一个很重要的原则：

> 再好的内容打法，最后都要回到“这套模式能不能复制、能不能赚钱”。

## 对当前项目最有用的通用版本

### 通用业务判断框架

1. 这个市场值不值得做？
2. 这个类目或题材值不值得做？
3. 这个产品或设计方向能不能承载品牌表达？
4. 这条内容链路能不能低成本验证？
5. 验证通过后，能不能复制？

### 通用执行框架

1. 收集市场与竞品信息
2. 提炼目标人群与内容角度
3. 选择首批测试题材/产品
4. 设计测试内容与验证指标
5. 记录结果并决定是否放大

## 对中国 POD 项目的适配建议

- 先不要照搬旧资料里的国家、类目和人数配置
- 要保留的是“判断维度”和“推进节奏”
- 第一轮只做一个最小主题，不要同时开太多方向
- 先验证内容 -> 题材 -> 转化的基本闭环

## 在 OrbitOS 里的落地方式

- `00_收件箱`: 收集素材、竞品、灵感
- `30_研究`: 市场、国家、题材、类目分析
- `40_知识库`: 沉淀可复用概念，如“内容逻辑”“品牌表达”“题材测试”
- `20_项目`: 真正执行某个主题或自动化链路
