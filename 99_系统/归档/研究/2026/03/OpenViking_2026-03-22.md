# OpenViking

> 一手来源：[volcengine/OpenViking](https://github.com/volcengine/OpenViking)

## 一句话判断

`OpenViking` 最值得你关注的，不是“又一个记忆工具”，而是它把 `记忆 / 资源 / 技能` 统一成同一套上下文文件系统的思路。这和你现在正在搭的 `OpenClaw + Obsidian + 记忆层 + 角色层` 非常接近，但它更偏“Agent 的上下文基础设施”，不是直接替代 Obsidian 的笔记系统。

## 学习深度

- 当前学习深度：`摘要级`
- 当前判断依据：

  - 已确认项目定位、核心能力、Quick Start、依赖要求

  - 它和你当前系统的相似点与差异
- 当前还不能确认什么：
  - 本机部署复杂度
  - 与 OpenClaw 现有运行时的真实集成成本
  - 你这套流程里替换哪一层最划算

## 它主要在解决什么问题

根据官方 README，OpenViking 把 Agent 开发里最常见的 5 个痛点提得很清楚：

- 上下文碎片化：记忆、资源、技能散在不同地方
- 上下文需求持续膨胀：长任务会不断产出上下文
- 检索效果差：传统平铺式 RAG 难以看全局
- 检索不可观测：出了问题不容易知道卡在哪
- 记忆迭代弱：只记用户对话，不记 Agent 做事经验

对应的核心方案是：

- 用文件系统范式统一 `memories / resources / skills`
- 用 `L0 / L1 / L2` 分层上下文减少 token 消耗
- 用目录递归检索提高上下文命中率
- 用可视化检索轨迹提高可观测性
- 用自动 session 管理让记忆能自迭代

## 为什么它和你当前系统高度相关

你现在已经在手工做的事情，其实和 OpenViking 的方向高度同构：

- 你在做 `收件箱 / 研究 / 知识库 / 角色摘录 / SOP / 模板`
  - 这很像在手工维护 Agent 的资源层、知识层和经验层
- 你在做 `memory-lancedb`、角色记忆、自审 / 审核 / 复盘
  - 这很像在手工补 Agent 的记忆层和自迭代层
- 你在做 `谋士 -> 专家角色 -> 审核`
  - 这很像在手工设计上下文如何被不同角色读取和更新

所以它和你的关系不是“完全新概念”，而是：

`你现在已经在用 Obsidian 手工搭这套结构，OpenViking 提供的是更底层、Agent 原生的统一上下文基础设施。`

## 和你当前系统的关键差异

### 1. 它更像 Agent 脑子，不像人的笔记库

- `Obsidian`
  - 更适合人类阅读、整理、复盘、表达和长期知识沉淀
- `OpenViking`
  - 更适合 Agent 在运行时组织、加载、检索和迭代上下文

所以它不该被理解成“取代 Obsidian”，更像：

`OpenViking 管 Agent 的上下文基础设施，Obsidian 管你的显性知识和项目资产。`

### 2. 它更偏基础设施，不是轻量小补丁

从官方 README 可以看到，它有这些前置要求：

- Python 3.10+
- Go 1.22+
- GCC 9+ 或 Clang 11+
- 稳定网络
- VLM 模型
- Embedding 模型

这说明它不是“装个插件就好”的级别，而是偏完整上下文平台。

### 3. 它的优势更适合中后期系统升级

它最强的地方在：

- 上下文分层加载
- 统一管理 `记忆 / 资源 / 技能`
- 检索轨迹可观测
- session 自迭代

这些都更像“你系统逐渐变复杂之后的基础设施升级”，而不是现在第一优先要替换的东西。

## 当前最值得借鉴的 4 个点

### 1. 统一看待 `记忆 / 资源 / 技能`

这是它最值得你直接借鉴的地方。你现在已经在分开做这些层，但还没有把它们明确当成“一套上下文系统”统一治理。

### 2. 分层上下文加载

`L0 / L1 / L2` 这个思路非常适合你现在的学习深度分级、研究层级和知识沉淀层级。

你完全可以在现有系统里类比成：

- `L0`
  - 标题级 / 摘要级线索
- `L1`
  - 研究草稿 / 结构化摘要
- `L2`
  - 全量内容 / 实操复盘 / 稳定知识

### 3. 检索轨迹可观测

你现在已经很强调“留痕、可追溯、日记同步、流转记录”。OpenViking 的“可视化检索轨迹”与这套价值观非常一致。

### 4. session 自迭代

这和你现在的 `角色摘录 -> 知识卡 -> 复盘更新` 很接近。它的启发不是“自动化更炫”，而是：

`Agent 的做事经验也应该被持续提炼，而不只记用户偏好。`

## 当前不建议马上做的事

- 不建议现在就把 Obsidian 替换成 OpenViking
- 不建议现在就把整个运行栈迁到 OpenViking
- 不建议在还没打通你现有“链接学习默认动作”之前，再引入一整套更重的上下文基础设施

## 当前更建议做的事

先借思路，不急着全量接入：

1. 先把你现有系统里的 `记忆 / 资源 / 技能` 统一画成一张结构图
2. 先把“学习深度分级”类比成上下文分层加载
3. 先把“角色经验沉淀”做得更像 session 自迭代
4. 等你现有链路跑稳，再评估要不要把 OpenViking 当下一代底层

## 当前结论

- `OpenViking` 值得继续深挖
- 但它对你现在的价值，首先是“设计对标”，不是“立刻替换”
- 如果只选这期里一个最值得继续研究的项目，它和 `awesome-openclaw-skills` 都排在第一梯队
- 两者分工也不同：
  - `OpenViking` 偏底层架构升级
  - `awesome-openclaw-skills` 偏能力池扩容
