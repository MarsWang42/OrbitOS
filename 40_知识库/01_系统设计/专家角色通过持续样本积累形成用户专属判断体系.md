# 专家角色通过持续样本积累形成用户专属判断体系

## 核心原则

专家角色不应只把用户发来的链接、图片、视频和案例当作一次性输入，而应通过持续样本积累，逐步形成“更适合这个用户”的判断体系。

这里长出来的，不是抽象的通用结论，而是：

- 用户专属审美
- 用户专属来源偏好
- 用户专属表达偏好
- 用户专属实现偏好
- 用户专属风险边界

## 为什么这很重要

如果没有样本积累，角色每次都只是在“临场生成”。

如果有了稳定样本积累，角色会逐渐形成：

- 更贴近用户的专业判断
- 更少跑偏的建议
- 更高复用度的经验
- 更稳定的风格和边界感

## 每个角色应该积累什么

- `diaoyan`
  - 来源可信度口径
  - 对标样本标准
  - 什么算值得继续深挖
- `sheji`
  - 审美偏好
  - 不喜欢的元素
  - 什么风格适合当前项目，什么只是“好看但不适合”
- `yinxiao`
  - 用户接受的传播语气
  - 哪类切入角度更像用户会认可的打法
- `yewen`
  - 语言节奏
  - 标题风格
  - 用户更偏好克制、直接，还是更有画面感的表达
- `jishu`
  - 用户偏好的实现复杂度
  - 可接受的依赖、自动化深度和维护成本
- `shuju`
  - 用户真正关心的指标
  - 什么数据在用户这里算“能支持判断”
- `shenhe`
  - 用户对风险、质量和放行的底线
  - 哪类问题必须拦下，哪类问题可在边界内放行

## 样本积累不等于素材囤积

这里最容易跑偏的地方是：把“积累样本”误做成“堆越来越多素材”。

更稳的链路应是：

`样本输入 -> 判断与分类 -> 去重 -> 提炼偏好信号 -> 角色摘录 -> 验证 -> 再决定是否进入研究或知识`

所以真正要保留的，不是所有原始素材，而是：

- 哪类样本有代表性
- 哪些信号反复出现
- 哪些是正偏好
- 哪些是反偏好
- 哪些已经被验证

## 用户专属判断体系的两面

只记录“喜欢什么”还不够，还要记录：

- 明确喜欢的样本
- 明确不喜欢的样本
- 暂时欣赏但不适配当前目标的样本

因为真正可用的判断体系，往往同样依赖“排除法”。

## 标准沉淀路径

推荐把这条路径理解成：

`用户给样本 -> 专家角色做比较与标注 -> 角色摘录记录判断信号 -> 多次出现后形成经验 -> 经过验证再提炼成正式知识`

## 边界

- 原始样本不是知识
- 单次偏好不等于稳定偏好
- 没验证过的感觉，不应伪装成规律
- 不应因为某角色积累了样本，就把正式知识按角色切碎存放
