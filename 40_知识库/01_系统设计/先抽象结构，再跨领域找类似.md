# 先抽象结构，再跨领域找类似

## 核心原则

很多有效方法不是因为“事情表面一样”才可复用，而是因为它们底层结构相似。更稳的做法是先抽象结构，再去不同事情里找类似模式。

## 默认顺序

`先抽象当前问题结构 -> 再找同类结构的样本 -> 再比较差异 -> 再决定哪些可迁移`

## 常见可复用的结构

- 获取受阻 -> 找替代入口 -> 回到主目标
- 信息不足 -> 先补锚点 -> 再判断方向
- 方案太多 -> 先找对标 -> 再做小验证
- 新渠道出现 -> 先进候选池 -> 验证后再纳入正式渠道池

## 系统要求

- 不只在同平台、同主题里找类似
- 也要在学习、工作、项目、生活决策里找结构相似点
- 迁移时不能只抄表面动作，要先判断约束和边界是否一致
