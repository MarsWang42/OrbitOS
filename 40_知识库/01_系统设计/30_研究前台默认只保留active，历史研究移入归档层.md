# 30_研究前台默认只保留active，历史研究移入归档层

## 当前判断

- `30_研究` 前台不应同时堆着 `active / archived / complete`。
- 更稳的做法是：
  - 前台只保留 `active`
  - 其余历史研究统一移入 `99_系统/归档/研究/YYYY/MM/`
- 这样用户打开研究区时，默认看到的就只是“还要继续推进什么”。

## 为什么现在这样判断

- 只靠 `status` 区分还不够，前台视觉上仍然会被大量历史研究占满。
- 研究的默认角色不是收藏，而是承接当前还未收口的问题。
- 如果前台和归档混在一起，用户仍要先做一轮筛选，系统就没有真正替用户减负。

## 适用边界

- 适用：
  - `30_研究` 目录的前台可见层
  - 已经是 `archived` 或 `complete` 的研究页
- 不适用：
  - 仍在推进、仍需补样本或补验证的 `active` 研究
  - 需要保持前台展示的特殊索引页

## 默认动作

1. 先按研究状态完成判断与分流
2. `active` 留在 `30_研究` 前台
3. `archived / complete` 移入 `99_系统/归档/研究/YYYY/MM/`
4. 同步修正引用路径，避免项目、知识卡和历史记录断链

## 触发更新

- 如果以后 `30_研究` 需要承担更重的展陈作用，这张卡需要重审
- 如果出现新的研究看板层，能替代“前台 + 归档”结构，也需要更新
- 如果发现某类 `complete` 研究必须留在前台才有更高使用价值，也需要修正边界

## 判断演化

- `v1`
  - 当时怎么想：只要把 `status` 写清楚，研究区就已经足够可用
  - 依据是什么：逻辑上可以分辨 `active / archived / complete`
  - 局限是什么：视觉上仍是大量研究堆在一起，用户还是得先筛
- `v2`
  - 被什么新知识冲击：日记前台已经通过“现在 / 过去”和归档层明显变轻，研究区仍显得拥挤
  - 改成了什么：`30_研究` 前台默认只保留 `active`，历史研究移入归档层
  - 为什么升级：这样研究区才能真正回答“现在要继续哪条研究”
- `v3`
  - 当前版本：前台只留 `active`，历史研究移到 `99_系统/归档/研究/YYYY/MM/`
  - 与上一版相比删掉了什么：删掉了“前台靠状态硬区分”的做法
  - 保留了什么：依然保留全部历史研究，只是不再让它们占前台
