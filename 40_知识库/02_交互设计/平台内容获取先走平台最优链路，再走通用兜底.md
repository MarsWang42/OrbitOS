# 平台内容获取先走平台最优链路，再走通用兜底

## 核心原则

判断一条内容能不能被深学，不应先被“某个工具能不能抓”绑死，而应先判断当前平台的最优获取路径，再决定是否退回通用工具、登录态补救或手动兜底。

## 默认顺序

`先识别平台 -> 先走平台最优链路 -> 再走通用链路 -> 再补 cookies / 登录态 / 权限 -> 最后才手动兜底`

## 当前这套系统里的默认理解

- `B站`
  - 优先：`yt-dlp`
  - 再看：章节、描述、字幕、cookies
- `YouTube`
  - 先试：`yt-dlp` 元信息 + 字幕
  - 如遇 anti-bot：先停在元信息 / 轨道确认层
  - 仍无正文：直接转人工片段验证，不默认上代理
- `抖音`
  - 优先：平台专用链路，如 `douyin-mcp-server`
  - 再补：`yt-dlp`、fresh cookies、网页登录态

## 系统要求

- 不得因为一个通用工具失败，就把整个平台直接判死
- 无论最终走哪条链路，都要回写：
  - 当前用了哪条获取路径
  - 拿到了什么层级的信息
  - `learning_depth` 当前属于哪一档

## 当前样本支撑

- `B站`
  - 真实样本：[[99_系统/归档/研究/2026/03/OpenClaw零基础系统教程_2026-03-22]]
  - 已确认：`yt-dlp` 匿名链路能稳定拿到标题、UP 主、时长、章节
  - 当前收口：B站默认先拿结构化元信息与章节，把线索从 `标题级` 升到 `摘要级`
- `抖音`
  - 真实样本：[[99_系统/归档/研究/2026/03/GitHub一周热点第107期_2026-03-22]]
  - 已确认：同一条分享链上，`yt-dlp` 会报 `Fresh cookies (not necessarily logged in) are needed`
  - 已确认：`douyin-mcp-server` 能返回 `video_id / title / download_url`
  - 当前收口：抖音默认先走平台专用链路，再按需补 `yt-dlp / cookies / 登录态`
- `YouTube`
  - 真实样本：`OpenClaw Tutorial for Beginners - Crash Course`
  - 已确认：`yt-dlp --flat-playlist` 能拿到标题、频道、时长和 `watch` 链接
  - 已确认：对正式 `watch` 链接继续执行 `-J / --list-subs / --cookies-from-browser chrome` 仍可能被 `Sign in to confirm you’re not a bot` 挡住
  - 已确认：`youtube-transcript-api 1.2.4` 对同一条视频也可能返回 `RequestBlocked`
  - 已确认：本机 `yt-dlp 2026.3.3` 的 `--impersonate chrome` 当前不可用，因为缺少对应依赖
  - 已确认：browser 方案能在已登录页面源码里读到 `captionTracks`，但对应 `timedtext` 当前返回 `200` + 空正文
  - 当前收口：YouTube 先试 `yt-dlp`，但不要把字幕当默认承诺；`transcript API` 也不是稳定兜底；browser 方案目前只能确认轨道存在，当前默认直接转人工片段验证，不再把代理当默认下一步
